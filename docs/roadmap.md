| 136 | **Stalled-filesystem bound for migrate-storage (process-isolated copy)** | The `migrate-storage` execution deadline (`migrateStorageTimeout`, 2h) does not hold against a stalled filesystem, and a pure wall-clock cap cannot distinguish "slow but progressing" from "stalled". Every filesystem syscall in the copy path ignores the context — `Stat`, `ReadDir`, `MkdirAll` in `storage.CopyTree`, `Open`, `OpenFile`, `Chtimes` in `copyFile`, `MkdirAll`/`ReadDir`/`Rename`/`RemoveAll` in `configtask.movePath` — and the per-file watchdog covers only the `io.Copy` phase: on expiry it closes the source file, which aborts healthy copies at the next chunk boundary (why long-but-healthy migrations are correctly bounded) but cannot interrupt a read already blocked inside the kernel — Linux `close(2)` does not abort an in-flight read, and Go's `poll.FD.Close` only wakes poll-waiters (`evict`) and then waits (`runtime_Semacquire`) for the in-flight read to finish. On an NFS hard mount with the server down, a dead FUSE backend or a hung disk, the read never returns: the handler goroutine never comes back, the task stays `processing` forever (the heartbeat keeps the lease fresh, so the reaper cannot reclaim it) while holding `LockMaintenance` and waiting for `LockStorage` — consume/enrich/thumbnails/backup stall behind it, and the wizard's setup gate polls a task that will never settle. Local ext4/xfs with a dead disk is not affected the same way (the kernel retries and returns `EIO` within minutes). Proposed direction: run the bulk copy in a supervised child process (the dispatcher already forks `kushim --executor migrate --from-batch` — no new machinery), enforce the bound by progress liveness — a per-entry/byte progress callback so "no progress for N minutes" or the wall-clock cap triggers `SIGKILL` of the child, which does reach the killable states NFS-hard and FUSE use — then fail the task into the existing retry path (a retry naturally resumes: entries already moved are gone from the source listing, and re-copies `O_TRUNC` whatever a partial write left); document that a truly wedged disk's D-state can defeat even `SIGKILL`, replace the pure wall-clock cap with the progress-stall rule so genuinely large healthy migrations are not killed mid-way, and correct the handler comment that currently claims the deadline bounds copies it cannot reach. |
