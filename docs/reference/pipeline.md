# Consumption Engine (`internal/documents/consumption/`)

## `consumer.go`

### Structs

- `Consumer`
  - **Fields**: `config *config.Config`, `logger *log.Logger`, `client *database.Client`, `runner runner` (interface, satisfied by `*tools.Runner`)
   - **Methods**:
     - `NewConsumer(cfg, logger, client) (*Consumer, error)` — Validates `PdfOptimizer.Fallback` at startup
     - `NewConsumerWithRunner(cfg, logger, client, runner) (*Consumer, error)` — DI variant
      - `Process(ctx, file File, documentID string, report task.ProgressFunc) (File, error)` — Convert → Extract → OCR fallback → optimize → store (creates document with PageCount, WordCount, CharCount). For image MIME types (`image/*`), skips text extraction entirely and routes directly to OCR. `report` is the per-task progress callback (pass `task.NoopProgress` to report nothing).
       - `convertToPdf(ctx, file File, documentID string) (File, error)` — When `consumer.converter.enabled` and the file MIME is DOCX/ODT, runs LibreOffice headless to produce a PDF. Sets `file.ConvertedPdfTmpPath`. Pipeline re-routes text extraction, page counting, and optimization to the converted PDF. The original office document is preserved in storage.
       - `extractText(ctx, file File, documentID string) (File, error)` — For PDFs: uses `minTextDensityRatio` (0.001) to decide OCR vs text. For images (`image/*`): sets `PageCount=1`, calls OCR immediately without attempting text extraction. For DOCX/ODT with the converter disabled: extracts text via `CompositeExtractor` (MIME-dispatched to the DOCX or ODT adapter), skips PDF optimization, and stores the processed file with its original extension (`.docx`/`.odt`) since no OCR or optimization occurs.
     - `isDuplicate(ctx, path) (bool, error)` — MD5 → SHA512 two-step duplicate check

- `File`
  - **Fields**: `Name`, `OriginalPath`, `OCRTmpPath *string`, `OptimizedPdfTmpPath *string`, `ConvertedPdfTmpPath *string`, `StorageProcessedPath *string`, `StorageOriginalPath *string`, `DocumentID string` (UUID), `DocumentDbId sql.NullInt64` (DB auto-increment ID), `MD5Checksum`, `SHA512Checksum`, `Text sql.NullString`, `MimeType`, `Date time.Time`, `FileSize int64`, `PageCount int`. When the converter is enabled and the file is DOCX/ODT, `ConvertedPdfTmpPath` holds the path to the LibreOffice-generated PDF. PDFs and OCR'd images are stored as `.pdf`; converted documents are also stored as `.pdf` (processed) with the original preserved as `.docx`/`.odt`; native-format files (DOCX, ODT) that didn't need conversion or OCR preserve their original extension. Originals always preserve their real extension (e.g. `documentID.png`).

### Functions

`calculateSHA512`, `countPages(path) int` — Uses MuPDF to count PDF pages

`MoveFailedFile(storageDir, originalPath, errType, logger, docID)` — Moves a failed file from the inbox to `storage/errors/<uuid>-<filename>.pdf`. If `errType` is `"duplicate"`, moves to `storage/errors/duplicated/`. Creates destination directories as needed. Handles non-existent source files gracefully (logs error, no-op).

`QuarantineFailedFiles(ctx, queries, storageDir, logger, batchID) error` — For a batch with recently-quarantined consume tasks (status=`failed`, error `LIKE 'Max retries exceeded%'`), moves each task's inbox file to `storage/errors/` via `MoveFailedFile`, then runs the batch-scoped sweep `DiscardWaitingEnrichesOfFailedConsumes` — discarding **every** still-`waiting` enrich whose consume in the batch is `failed` (copying the parent's error text), executed unconditionally so it also catches legacy stuck data beyond `'Max retries exceeded'` tasks. Called from `reclaimStaleBatches` (queue daemon) and the CLI resume path (`consume.Run`). Returns the first error encountered (continues processing remaining tasks on error).

- MD5 checksum computation is in `storage.CalculateMD5` (`internal/documents/storage/files.go`) — see [Config & Utils](config-and-utils.md)

## `scan.go`

### Functions

- `ScanAndEnqueue(ctx, cfg, client, logger) (batchID string, enqueued int, err error)` — Shared inbox scan → dedup → batch creation function. Scans the consumption directory via `storage.ListFilePaths`, computes MD5 for each file, batch-deduplicates against existing documents via `queryDuplicatesByMD5`, and creates consume+enrich task pairs. Scan-time duplicates are **moved** to `storage/errors/duplicated/` (via `MoveFailedFile(..., "duplicate", ...)`) instead of being skipped in place: a file whose MD5 matches an existing document is only quarantined when its SHA512 also matches the stored `sha512_checksum` (an MD5 collision with a differing SHA512 is enqueued normally), and a second copy of a file already enqueued earlier in the same scan is moved too (guarded by the `consume:<md5>` dedup key). The batch record is created **after** all tasks are committed (with status `queued`) to prevent the queue consumer from picking up an incomplete or empty batch. Returns an empty batch ID when no files or all duplicates are found.
- `queryDuplicatesByMD5(ctx, client, hashes) (map[string]duplicateInfo, error)` — Single SQL query (`SELECT md5_checksum, document_id, sha512_checksum FROM document WHERE md5_checksum IN (...) AND deleted_at IS NULL`) for all MD5 hashes, returns a map keyed by MD5 → `duplicateInfo{documentID, sha512}` for O(1) lookups in the dedup loop. The `deleted_at IS NULL` filter keeps parity with the consume-time checksum lookups (`GetDocumentByMD5Checksum`/`GetDocumentBySHA512Checksum`) so soft-deleted (trashed) documents never trigger quarantine.

# Enrichment Engine (`internal/enrichment/`)

## `enricher.go`

### Struct

- `Enricher` — `config`, `logger`, `client *database.Client` (transaction access for the persist step; `queries` is `client.Queries`), `runner`, `tag *curation.Tag` (tag persistence), `admission *admission.Adjudicator` (the admission seams: compound decomposition, identity planning, and the tag-quality decision)
  - **Methods**:
    - `NewEnricher(cfg, logger, client, tag *curation.Tag, matcher matcher.Matcher) *Enricher` — Creates runner via `NewRunnerWithMatcher` with textreducer, contentanalyzer, tagmatcher tools and builds the `Adjudicator` over the same runner; matcher is either a direct `*Hugot` (in `kushim` CLI) or a `*matcher.MatcherClient` (in `edub` API server) — both satisfy the same `matcher.Matcher` interface.
      - `Enrich(ctx, document, report task.ProgressFunc) (*json.RawMessage, error)` — Full pipeline:
       1. Dual text reduction: LLM-targeted and tag-matching-targeted (via `matcher.TargetWordCount`)
       2. Fetch doc types, people types from DB; all tags via `tag.ListAll` (unfiltered — the novel-set comparison must see quarantined names). The enricher splits the rows in one pass: promoted names feed the embedding-store trust set and the `MatchTags` fallback vocabulary, while provisional names only feed the novel-set (`dbNames`) and the deleted-tag merge-target existence check.
       3. Semantic tag matching: passes tag names to `Runner.MatchTags`. In `kushim`, embeddings are resolved via the local Hugot store (cache-miss encoded on the fly). In `edub`, the `MatcherClient` forwards requests over the Unix socket to the external matcher process. Only matches at or above `enricher.tagmatcher.min_suggestion_similarity` are kept as suggestions (an empty list when none clear the bar). Falls back to the promoted vocabulary on failure — but only when it has at most 200 names; beyond that the fallback is empty suggestions and the prompt omits the tag-preference clause entirely (an oversized list would crowd out the document text).
       4. **Token budget pre-check**: The content analyzer's `Analyze()` method builds the full prompt, calls the analyzer's `estimateTokens` (character-based heuristic with CJK detection), and if the estimate exceeds `caps.MaxInputTokens`, returns a `ContentTooLargeError`. No HTTP call is made. The enricher catches this error in a retry loop (up to 2 iterations), computes a proportional word-target reduction (`maxTokens / actualTokens * 0.9`), re-runs TextRank from the original document text, and retries. If the document still can't be reduced below `minTargetWords` (100), the task fails with a clear "document too large for model X/Y" error.
       5. LLM content analysis (title, doc type, tags, people, language). If the analysis returns entirely empty (all fields blank/default), enrichment retries once; if still empty, the task is marked `failed` for visibility and manual retry.
       6. **Response-time token limit fallback**: If the provider rejects the request with a context-length error (OpenAI/DeepSeek format), `doRequest()` returns a `TokenLimitError` via `parseTokenLimitError()`. The enricher's retry loop catches this and applies the same proportional re-reduction + retry logic. For providers whose error format doesn't match the regex, the error propagates as a generic API failure.
       7. **Tag normalization** — LLM-extracted tags are run through `NormalizeTags` (delegates to `textnorm.NormalizeTag`: NFKC, lowercase, dash family → space, accent folding, keeps letters of any Unicode script, digits, and `+ # .`, strips everything else, collapses whitespace), then deduplicated and empties rejected
       8. **Facet separation + tag filtering** — `SeparateFacets` first gates typed tags by the `category` the model assigned them: `form_genre` tags (they belong in `document_type`) are dropped and logged as `tags[facet]: drop …` with `reason=matches_document_type` when the term normalizes to an existing document-type name and `reason=model_self_classification` otherwise; `person` tags are dropped with `reason=people_facet`; `work` tags are dropped with `reason=forbidden_category`; `place` tags survive only when the term is a whitelisted country or continent, otherwise they are dropped with `reason=non_whitelisted_place`. `topic` and `other` always survive, and tags without a detail row (untyped emissions) are not gated. `FilterTags` then drops deterministic garbage tags: tags with >3 tokens, tags that share any token with a person's name (from the current document), multi-word tags (≥2 tokens) whose tokens form a strict subset of any known person in the full `people` table, and tags whose token set is a subset of the title's token set (the title-echo rule applies to whole emissions only — split components are exempt). No count cap is applied.
       9. **Compound decomposition** — `Adjudicator.DecomposeTags` replaces compound tags (2–3 words, Latin script, at least one content part — `tags.ClassifyShape` = `ShapeCompound`) with their parts. A compound whose key already exists in the store — tag names and alias names via `ListStoreTagKeys`, house-formed with `tags.Key` — is an application, not a candidate, only once a current-version composition verdict decides it: it is then skipped before judgment (DEBUG `tag split[...]: skip` with `reason=store_existing disposition=…`) and produces no evidence row, while a decided keep applies its judged-dimensional parts alongside from the persisted cache on every emission (no model call). A store-existing compound with no verdict, or only a degraded `judge_unavailable` keep, stays a candidate and re-enters judgment (DEBUG `re-judged (reason=undecided)`) until a verdict exists; without an adjudicator no verdict is reachable, so it is skipped rather than appending a degraded row on every emission. With the tag adjudicator enabled the decision runs two context-free judged passes through a shared verdict store: a **parts pass** (`Runner.JudgeTagParts`, criteria pinned by `analyzer.TagPartDimensionVersion`) judges each fold-resolved content word on its own, and a **compound pass** (`Runner.JudgeTagCompounds`, pinned by `analyzer.TagSplitVersion`) reads the phrase as a named unit, a composition, or a phrase with no retrievable dimension. Fresh verdicts persist in `tag_part_dimension_event` (keyed by resolved value) and `tag_compound_status_event` (keyed by candidate), both version-filtered and first-writer-wins on a concurrent insert, so a value or compound seen across documents is judged once. Components are first fold-resolved through the store-anchored net (`tags.AnchoredFold`: the generated WordNet pertainym table's attested adjective→noun pairs, anchored only on promoted store values; two distinct store hits are ambiguity, never a fold; the shape-based derivational and morphographic proposals stay in the judged identity path) and are the split branch's components; they then pass `analyzer.SplitComponents` (normalize, dedupe, ≤3 words, ≤64 chars, the hard per-document token filters — the title-containment check does not apply to parts) and a split must yield 2..`tags.MaxCompoundWords` valid components; the compound stays whole otherwise. The two answer sets fold into `tags.CompositionFeatures` — the compound reading, the parts' dimensional reading, a judge-outage flag, cross-sample disagreement, and the reconstructibility signal (every part dimensional and a promoted store label) — and `tags.DecideComposition` disposes branch-first: the parts test selects the branch (all parts dimensional is the combination branch, a failing part the unit branch) and the compound reading disposes within it — split, keep (with its reason, and for keeps the judged-dimensional parts applied alongside), or drop. Without an adjudicator, only conjunction joints (`and`, `or`, `vs`, `vs.`, `versus` — detected by `textnorm.SplitJointTag`) split mechanically and every other compound passes whole. Every candidate returns one `tags.CompositionRow` — candidate, validated parts, disposition, reason, `criteria_version` (`analyzer.TagSplitVersion`), the fresh judge model (NULL for a cached verdict and the conjunction fallback), and `reconstructible` — and logs the matching `tag split[...]: split|keep|drop` line; an `invalid_components` keep logs the proposed parts at DEBUG, and a concurrent-writer disagreement logs a WARN naming both samples. A transient judge failure retries once; an incomplete reply salvages the entries it returned and defers only the missing ones (no row, `judge_unavailable`); a credit-exhaustion failure pauses the batch; every other failure keeps the compound.
       10. **Deleted-tag blocklist** — after decomposition, `Adjudicator.ApplyDeletedTagPolicy` consults the `deleted_tag` table (loaded once per run): `blocked` names are dropped and `merged` names are rewritten to their merge target (dropped when the target no longer exists as a tag, provisional targets included).
       11. **Identity** — `Runner.RankTags` ranks the surviving tags against canonical names, then `Adjudicator.PlanIdentity` applies aliases, M1 house form, and M3 key equality, flags mechanically proposed folds (M2 — the lemmatizer, the conservative plural strip, the store-anchored relational-adjective derivations, and the bounded morphographic proposal), and generates gate subjects via `policy.Evaluate` (identity; every remaining candidate neighbour becomes a gate subject — similarity never replaces). Proposed folds are confirmed by the identity judge and gate subjects are resolved by same-intent adjudication when `enricher.tag_adjudicator.enabled` is true: a pinned variant class (orthographic spelling variants, literal token permutations) resolves `same` mechanically with no judge call, and the rest are judged (`same` aliases the losing name onto the winner, `variant`/`related` register both); a partial reply decides the claims it returned and leaves only the missing ones pending in `tag_identity_event` with the candidate born provisional, resolvable by `kushim tagidentity` or the reconciler's identity sweep. A fold the gate refuses beside a live store value holds the birth for review — provisional plus an evidence-derived promotion hold that blocks inline and sweep promotion until resolved. A rank failure falls back to the deterministic planner (`tag.PlanRegistration`) and emits one `keep` line per tag with `reason=rank_unavailable` so the reconciler's log bootstrap sees the pair. A credit-exhaustion failure from the identity or pair judge pauses the batch instead of leaving the claim pending.
       12. **Tag admission decision** — when `enricher.tag_quality.enabled` is true, `Adjudicator.ApplyTagQuality` filters the consolidated list before persist. Novel tags (normalized names absent from the vocabulary) are resolved by the pinned rule set (`tags.DecideAdmission`) over their features: the judge's rubric answers — `subject_matter`, `dimension`, `not_person_place_work`, `atomic`, `not_form_genre`, plus the optional `defer` abstention — taken from the `tag_quality_event` cache or temperature-0 `JudgeTagQuality` calls over batches of up to 40 candidates per document (`Runner.JudgeTagQuality`; the prompt serves the reduced document text to the subject-matter question and judges the remaining criteria on the candidate, carrying each one's term/category/whitelisted-place note), plus the emission's deterministic signals (a detail annotated `other`, and a best store similarity below the internal `no_anchor_similarity` 0.60 cut). A judge abstention defers; two or more failing signals reject; exactly one defers to review (the gray band); none admits. Rejections drop the tag for that document — `Plan.DropTagNames` removes the registration and its pending identity evidence before persist, so the name is never stored — and log `tagquality[v4]: reject … (reason=corroborated_failures source=judge|cache …)`; defers are kept and logged too, and admitted candidates journal at DEBUG. After the gate, each composition row whose split lost an admitted part flips to `disposition=drop` with `reason=part_rejected` — parts resolved through the plan's input→output mapping (`admission.OutputByInput`) so renamed parts still match, keeping the row's resolved parts — and logs `tag split[...]: drop … (reason=part_rejected part=…)`; a keep row instead prunes the rejected parts from the parts it records, the compound standing whole. Fresh verdicts are recorded per `(tag_name, policy_version)` with the judging model and the recorded outcome, cache-applied ones with NULL `verdict_model`; a cached row re-runs the decision over the stored rubric with the current emission's deterministic signals, and rows predating the rubric or the outcome column fall back to their `pass` flag. A transient judge failure retries once; parse failures, incomplete replies, output-cap hits, credit exhaustion, token-limit, content-too-large and context errors are never retried. A reply that omits verdicts for some candidates salvages the entries it returned — each is decided and cached — and defers only the missing candidates with `judge_unavailable` (no verdict row; re-judged on re-emission). Every other non-credit failure keeps every novel tag with a defer decision (no verdict row), logged as a WARN naming the kept candidates (`tagquality[v4]: judge failed for …`); a credit-exhaustion failure aborts the document so the batch pauses. The decision thresholds are internal pinned constants, not config keys.
       13. New tags are created through a single plan application `tag.CreatePlannedTx(ctx, txQ, plan, quarantine)` — the plan carries registrations, alias actions, and identity evidence from step 11, plus the batch's composition rows from step 9 (the enricher stamps each with the document id), minus the names step 12 rejected; the same call writes the identity and composition evidence rows. Per-index results use `Created`/`Conflict`/`Apply`/`Alias`/`Invalid` statuses (a blocklisted name is never registered or aliased). `quarantine` is `enricher.tag_quality.enabled`: off, every `Created` row is promoted atomically with its insert (`PromoteTags`) so the birth is trusted; on, births land provisional (`promoted_at` NULL). The call runs on the persist transaction (`client.BeginTx`), so tag creation, the `ClearEnrichDocumentTags` sweep, the `AddDocumentTag` inserts (`source = 'enrich'`), the orphan-mark clearing for the assigned tags, and the verdict/evidence upserts commit or roll back together; any error aborts the task instead of leaving a partially tagged document. After the commit, a run that assigned zero tags logs a warning naming the `min_tags` floor — the per-document recall signal. With the layer on, `promoteEligible` then runs inside the same transaction over the provisional rows just touched: an admitted decision (the emission's, or the cached verdict row mapped through the decision for provisionals already in the store) plus assignments clearing the promotion floor (`tags.RecurrenceFloor`, 10 live documents; `CountLiveTagDocumentsByTagIDs` — trashed carriers are not evidence) sets `promoted_at` unless the name is identity-held (a refused fold beside a live store value) or composition-held (its latest composition verdict under the current split criteria version defers, conflicts, disagrees, is a reconstructible named unit, is a relational keep, or is a degraded judge_unavailable keep), each skipping it with a DEBUG (`identity hold %q (anchor=%q) — left for review` / `composition hold %q (reason=%s) — left for review`) — logged as `tagquality[v4]: promote %q (docs=%d reason=%s rule_set=decision-v4 floor=10)` — and the names are added to the embedding store via `tag.AddToStore` only after the commit; with the layer off the post-commit store add carries the batch's new names instead (and alias-removed names leave the store). Verdict-less provisionals (judge outage), unresolved folds, and pending same-intent claims are resolved later by the triggered `tagidentity` run, the scheduled reconciliation sweep's identity and provisional phases, or an operator through `GET /api/v1/tags/provisional` / `POST /api/v1/tags/{id}/promote`.
       14. Update document metadata — title is first rune-capped at 127 characters via `truncate` to enforce the server-side limit (independent of LLM prompt compliance), then persisted alongside doc_type and language
       15. Auto-detect OCR language: `ensureOCRLanguage` cross-checks LLM-detected language against configured OCR languages. If missing and the engine is gosseract, the tessdata download runs first (inside a background goroutine). The language is only appended to the in-memory config list and persisted to `config.yaml` on download success. A failed download leaves config untouched, so the next document detecting the same language retries the download naturally. A `sync.Mutex` protects the shared `Languages` slice against concurrent mutations from multiple enrich workers. For non-gosseract engines, the language is appended and persisted immediately (no tessdata needed).
       16. Manage document_people junction (clear + add) — for each person:
           - Determines canonical name via `canonicalPersonName`: uses LLM's `name_romanized` if provided (for non-Latin names), falls back to AnyAscii transliteration
           - Normalizes the canonical name via `textnorm.NormalizeForDB` (NFKC, lowercase, accent-folding, alpha-only) for normalized-name dedup lookup
           - Creates new people with `name` (canonical) + `name_native` (original non-Latin script) + `normalized_name` (computed from canonical) when no match found
           - Updates `name_native` on existing people if currently empty
           - Unknown people types default to `"unknown"`
